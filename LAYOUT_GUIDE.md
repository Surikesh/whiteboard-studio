# Diagram layout guide

These rules are the default contract for agent-generated Tldraw Lab diagrams. Apply them with [DIAGRAM_ROUTER.md](DIAGRAM_ROUTER.md) and the mandatory icon-led language in [VISUAL_STYLE_GUIDE.md](VISUAL_STYLE_GUIDE.md). Tldraw's `Editor.alignShapes`, `stackShapes`, and related transforms clean up existing selections; source specs should still start with deliberate coordinates.

## 1. Layout grammar and reading direction

Choose a routing profile from the explanatory grammar; routing is not universally orthogonal.

- **`orthogonal`** — default for architecture, flowchart, hierarchy, and grid-based comparison flows. Prefer top-to-bottom for hierarchical work; use left-to-right when the content or user requires it.
- **`linear`** — sequence diagrams, timelines, simple pipelines, and simple state transitions. Follow the axis that expresses order.
- **`graph`** — concept maps, causal diagrams, and dense dependency relationships. Curved or diagonal edges are allowed when they improve traceability.

Use one dominant reading direction by default, not as a hard law. Keep peers on a shared rank where the grammar has ranks. Put secondary systems such as storage, queues, and observability on a separate rank or side branch when that clarifies the main path.

## 2. Keep the canvas background clean

- Never create decorative background shapes, guide lines, columns, frames, or locked underlays.
- Never use Tldraw `semi` or patterned fills: their pattern can escape clipping on some browser/GPU combinations.
- Generated boxes use `fill: "none"` unless the user explicitly requests a solid fill.
- Alignment guides belong to editor interaction and must never persist as diagram shapes.

## 3. Grid and spacing defaults

- Icon-led asset node: 180 × 190; small technology asset inside a boundary: 100 × 150.
- Standard box: 240 × 120; health-specific service card: 260 × 150.
- For top-down ranked layouts, rows normally start every 280–320 px and peer columns every 360–400 px.
- Minimum clear gap between ordinary node borders: 140 px vertically and 120 px horizontally; prefer 180 px where an edge label needs a routing lane.
- Ranked peers share exactly the same coordinate on their rank. Repeated compact rows inside one boundary share exactly the same `x` and `w`.
- Keep a stroke-aware visible gap of at least 32 px between compact row rectangles. Touching/doubled borders and narrower gaps are collisions.
- Center parents over the full span of children when using a hierarchy.
- Keep a 160 px outer margin and 140 px below the title.

These are layout defaults. The hard outcome is readable visible spacing without overlap; later executable validators must report any rule they claim to verify.

## 4. Connector policy

### Hard invariants for every profile

- A connector must not pass through an unrelated node.
- Several connectors must never hide one another by sharing the same visible path.
- Edge labels must not overlap nodes, connectors, or other labels.
- Fan-in and fan-out paths must be independently traceable.
- Source and target bindings must be correct.
- Minimize crossings and handle unavoidable crossings explicitly where the renderer supports it.

Prefer adjacent-layer edges and keep labels short enough to remain on one clear segment. A useful default is 1–3 words, preferably under 14 characters, with 24 px whitespace and a clear segment around 160 px; rewrite rather than wrap when possible.

### Attach points

- A single-edge orthogonal chain uses side centers: bottom-center → top-center for downward flow, or right-center → left-center for horizontal flow.
- Orthogonal fan-in/fan-out uses distinct, evenly allocated attach points along the appropriate source/target side. Do not force multiple connectors through an exact center anchor when that would overlap their visible paths.
- Linear profiles use the anchors generated by their ordering grammar.
- Graph profiles may use side, perimeter, curved, or diagonal routing that best preserves traceability.

The loader owns generated endpoints from node geometry; labels must never fake routing. Distinct fan attachments are a documented target contract even where current tooling still requires manual geometry and rendered inspection.

## 5. Adaptive density

Apply the audience/detail budgets in `DIAGRAM_ROUTER.md`; there is no universal node limit. When content exceeds the selected view's useful budget, create an overview plus bounded detail views instead of shrinking labels or silently dropping facts. Use stable cross-reference labels and a fidelity ledger. Every view still has to answer its own focus question.

## 6. Preflight

Before opening a diagram, check what can be checked from its source:

1. Node rectangles do not overlap or visually touch after stroke allowance.
2. Compact rows have identical left/right edges and at least 32 px visible clearance; ordinary nodes preserve the selected spacing.
3. Ranks and direction match the selected grammar/routing profile.
4. No connector crosses an unrelated node or hides beneath another connector.
5. Edge labels occupy clear lanes and do not collide.
6. Single-chain center anchors or distinct fan attachments match the policy above.
7. Parent/child alignment and semantic grouping are deliberate.
8. Concrete entities use semantically correct icon-led assets; health cards appear only when health is the subject.
9. Content remains inside intended screenshot/export bounds.

Do not claim a prompt-only checklist item as machine-verified. After loading, inspect the actual rendered canvas at fit-to-canvas and at readable close-up zoom. If Tldraw text metrics cause wrapping, clipping, or collisions, adjust and reopen; JSON validity is not completion evidence.

## Tldraw cleanup API

```ts
// A vertical column of compact field rows:
editor.alignShapes(ids, "left");
editor.stackShapes(ids, "vertical", 32);

// A horizontal rank of ordinary nodes:
editor.alignShapes(ids, "center-horizontal");
editor.stackShapes(ids, "horizontal", 120);

editor.packShapes(ids, 100);
```

Always align first and stack second. Prefer `stackShapes` for deterministic non-negative gaps. Do not use `distributeShapes` as collision cleanup because it preserves the outer range and can create zero or negative clearance. After cleanup, render overview and readable close-up screenshots; geometry-only validation is insufficient. Bound arrows move with their shape clusters.
